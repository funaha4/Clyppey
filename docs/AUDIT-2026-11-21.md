# Clyppey 監査メモ 2026-11-21 — バグ・不足機能の洗い出し

5並列サブエージェントによる読み取り専用監査。`obj/bin` 除外。推測は明示。
規約の遵守確認: `-c:v copy` のみ・live系に `-pix_fmt` なし・fragment境界Take・BelowNormal（FfmpegExec/ClipWriter）・`-t` は `-i` の後ろ・apad/shortestなし — は概ね遵守。

## 最優先（実害あり・高）

### Engine/Ring/Audio
1. `ReplayEngine.cs:560-566` vs `678-681/245-248` — `FragmentRing.Clear()` が無ロック。停止・再接続の瞬間にポンプと競合しLinkedList破損の恐れ → EndSession/StartCaptureのring操作を `lock(_gate)` に統一。
2. `ReplayEngine.cs:568-584,521-534` — preserveBufferなのに音声は毎回Dispose→再接続前の音が消える＋`leadBytes` が数百秒窓で100MB級をlock内確保 → preserve時は音声も保持、leadは窓長でclamp。
3. `ReplayEngine.cs:182,541-597,743-754` — 録画中に再接続すると `_recordStream` を捨て、以後のfragmentがファイルに書かれない → Recording中のRestart禁止かrecord継続。
4. `ClipWriter.cs:107` — `WaitForExitAsync` にタイムアウトなし、`_busy` 保持のまま永久ブロック → 30秒タイムアウト＋Kill＋部分削除。
5. `ReplayEngine.cs:599-627,690-767` — 再接続の多重起動ガードなし。2つの `for(;;)` が並走し `_epochOffset` 上書き → single-flight化。
6. `FragmentedMp4Demuxer.cs:214-215` — Timescale取得失敗で全fragment Start=0、リングが約1秒に見える → fps推定フォールバック＋Error。
7. `AudioCapture.cs:522-539` — `WriteWindowWav` がlock内で巨大確保（最大2GB試行）→ 上限clamp＋lock外コピー、巨大時はvideo-only＋Warn。
8. `CaptureSession.cs:286-300`＋`DiskFragmentStore.cs:191-192` — 終了処理が直列で最大約11秒固まる → 並列化・短縮。

### Infra/Settings/Update
9. `UpdateService.cs:24,120-122` — HttpClient Timeout=20秒が90MB zipを殺す（36Mbps以上が必要）→ ダウンロード専用Infiniteタイムアウト。
10. `UpdateService.cs:49,114,174-197` — Version（タグ由来）を素通しで.cmdに埋め込み＋robocopy成否未検証 → 正規化値のみ使用、ERRORLEVEL>=8なら起動せず残置。
11. `AppSettings.cs:206-211`＋`MainViewModel.cs:854,885-894` — Loadの一時失敗→既定値→0.5秒自動保存で正常settings.jsonを上書き破壊 → Loadに結果区分、一時失敗時は自動保存抑止。

### Editing/FFmpeg・CLI
12. `TrimPlan.cs:179-194` — Exactは `h264_nvenc` 固定、Probe未参照。非NVENC機で全滅 → libx264フォールバックか事前無効化。
13. `Program.cs:164-172`＋`TrimJob.cs:126-138` / `Program.cs:476,522` — CLI trim/save/recordの `--out/--out-file` が無言上書き（エディタはMakeUniquePath済み）→ CLIも連番か--forceのみ上書き。
14. `Program.cs:25,30-41` — 不明コマンドがexit 0で成功扱い → defaultはexit 2。
15. `Program.cs:149-154` — trimで--removeと--keep併用時に--remove黙殺 → 拒否か警告。
16. `TrimJob.cs:266-270` — 失敗表示が先頭3行で真因（末尾）が出ない → TakeLast(3)。

### UI/多言語
17. `MainViewModel.cs:1581` — クリップ削除に確認なし（即File.Delete）→ YesNo（既定No）かゴミ箱。
18. `ClipEditorWindow.xaml.cs:1997` — 書き出し中(_busy)は確認なしに閉じられる → Cancel＋抑止。
19. `MainViewModel.cs:618` — マイク遅れ数値が更新されない（Raise漏れ）→ Delay setterでRaise。
20. `ClipEditorWindow.xaml.cs:136` — エディタは言語切替に追従しない → Loc.Changed購読。
21. `MainWindow.Hotkeys.cs:38` — ホットキーボタン追従漏れ＋エラー直書き → 切替時Refresh、資源化。

## 低・不足機能
- 低: ProbeCache非原子、Tray日本語直書き、Log単世代、concatエスケープ・非ASCII、toleranceが段数比例、MediaProbe fps誤読、音声テール推測、keepスリバー、IsFastStartデッドコード、pathsのHelp漏れ等。
- 不足（高）: 履歴サムネイル、削除ゴミ箱/Undo、Settings.SoundのUI欠落、更新アセットのハッシュ検証なし、排他フルスクリーン/HDR本対応なし（ddagrab固定）。
- 不足（中）: デバイスComboBoxラベル、デスクトップ側ピーク/数値、ホットキー競合の常時表示、更新の定期確認、TryEnsureWritable残骸掃除、benchのCSV出力、trimの残り時間表示。
- 乖離: AGENTS.md§8と§13でselftest秒数不一致（18 vs 16）、Debugパス固定、§9「17項目」は映像・保存系のみ（音声内容なし）、開発引数のApp/CLI区別なし、BuildSettingsオプションのHelp漏れ、終了コード表なし。
