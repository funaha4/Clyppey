# Clyppey — インスタントリプレイ

**NVIDIA のインスタントリプレイ（ShadowPlay）と同じ方式で、ゲームの FPS を落とさずに「直前のプレイ」を保存する Windows アプリです。**

常時録画しておき、ホットキーを押した瞬間に *過去 N 秒* を MP4 として書き出します。
書き出しは **再エンコードなし**（エンコード済みデータの stream copy）なので、押してから 1 秒以内にファイルが出来上がります。
**マイク音声の同時録音**、**英語 / 日本語の切り替え**にも対応しています。

> **画面**: 上から「モニター選択 → 保存できる長さ → 保存先 → 画質 → 音声 → ホットキー → 起動と動作」。
> ホームは状態・秒数・バー・数値・クリップだけを並べた最小構成です。
> UI は英語 / 日本語を切り替えられます。

## すぐ使う（ビルド不要）

**[⬇ Releases からダウンロード](https://github.com/funaha4/Clyppey/releases/latest)**

1. `Clyppey-x.y.z-win-x64.zip` をダウンロードして展開
2. `Clyppey.exe` をダブルクリック（**ffmpeg 同梱・.NET のインストール不要**）
3. トレイに常駐して自動で待機します。ゲーム中に **Ctrl + Alt + F10** で直前を保存

> `C:\Apps\Clyppey` など、OneDrive の同期対象ではない場所に置いてください。
> 設定と一時バッファは `%LOCALAPPDATA%\Clyppey` に作られます。

## なぜ FPS が落ちないのか

NVIDIA のインスタントリプレイが軽い理由は「映像が GPU から一歩も出ない」ことです。Clyppey も同じ経路を採っています。

```
ゲーム (GPU)
   │  DXGI Desktop Duplication
   ▼
D3D11 テクスチャ  ──── ここから先すべて GPU 内 ────┐
   │                                              │
   ▼                                              │
NVENC (GPU のエンコーダ)                          │
   │  圧縮済み H.264/HEVC/AV1                     │
   ▼                                              │
リングバッファ（エンコード済みバイト列）◄───────┘
   │
   ▼  ホットキー
ffmpeg で stream copy（再エンコードなし） → MP4
```

1. **キャプチャは GPU 上** — ffmpeg の `ddagrab`（Desktop Duplication API）が返すのは D3D11 ハードウェアフレームです。ピクセルが CPU 側メモリにコピーされることはありません。
2. **エンコードも GPU 上** — `h264_nvenc` はその D3D11 フレームをそのまま受け取れます（`hwdownload` を挟まない＝ゼロコピー）。ここが最重要で、`-pix_fmt` を指定するだけでこの経路が壊れて CPU 変換が入ります。本アプリは指定しません。
3. **バッファはディスク**（既定）— 1 秒単位のキーフレーム境界で分割した「フラグメント」を一時ファイルとして書き、古いものから消していきます。メモリ使用量はバッファ長に比例しません（設定で RAM 方式にも切り替え可）。
4. **保存時も再エンコードなし** — 保持していたフラグメントを連結し、`-c:v copy` で MP4 に詰め替えるだけ。60 秒のクリップでも数百ミリ秒で完了します。
5. **エンコーダは低優先度** — ffmpeg プロセスを `BelowNormal` で起動し、ゲームのスレッドを邪魔しません。

### 実測値（RTX 3080 Ti / 1920×1080 / 60fps）

| 指標 | 値 |
| --- | --- |
| 録画プロセスの CPU 使用率 | **0.1 – 0.5 %**（全コア合計） |
| GPU エンコーダ使用率 | 21 – 30 % |
| キャプチャ実測 fps | 59.0 – 59.5 fps |
| フレームドロップ | 0 – 1 |
| 60 秒保存にかかる時間 | 約 0.5 秒 |
| マイク入力の実測ピーク | −28.8 dB（無音ではない） |

`selftest` コマンドで自分の環境でも同じ検証ができます（後述）。

## 動作要件

- Windows 10 / 11 (x64)
- .NET 8 デスクトップランタイム（`Microsoft.WindowsDesktop.App 8.x`）
- エンコーダはいずれか 1 つがあれば動作します
  - **NVIDIA NVENC**（推奨・ゼロコピー）
  - AMD AMF / Intel QSV（フォールバック）
  - CPU の x264 / x265（最終フォールバック。負荷は上がります）

### 同梱 ffmpeg について

`tools/ffmpeg/ffmpeg.exe` は **gyan.dev の ffmpeg 7.1 essentials ビルド**（GPL）です。

最新の ffmpeg 8/9 系ではなく 7.1 を同梱しているのは、**NVENC API のバージョン問題**があるためです。

- ffmpeg 8/9 は NVENC API **13.x** を要求 → ドライバ 570 以降が必要
- ffmpeg 7.1 は NVENC API **12.2** を要求 → 古いドライバでも動き、新しいドライバでも動く

検証機（GeForce ドライバ 552.44 = NVENC API 12.2）では ffmpeg 9 では
`Driver does not support the required nvenc API version. Required: 13.1 Found: 12.2`
となり NVENC を使えませんでした。7.1 に替えたところ問題なく動作しています。

ffmpeg が無い場合は次で取得できます。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup-ffmpeg.ps1
```

## ソースからビルド

```bat
:: ビルドして %LOCALAPPDATA%\Programs\Clyppey に配置（デスクトップにショートカット作成）
install.cmd

:: 以降はデスクトップの Clyppey から起動
```

> **リポジトリ内の exe を直接起動しないでください。** 監視・制限のかかったフォルダ（OneDrive 配下など）に置いた exe は、
> そのフォルダの制限を引き継いで「ビデオ」フォルダなどへ書き込めないことがあります。
> `install.cmd` は exe と ffmpeg を通常のアプリ領域に複製するので、この問題を避けられます。

手動で行う場合:

```powershell
dotnet build src\Clyppey.App\Clyppey.App.csproj -c Release
src\Clyppey.App\bin\Release\net8.0-windows\Clyppey.exe
```

初回起動時に、利用可能なエンコーダを実際に起動して確認します（数秒）。結果はキャッシュされ、2 回目以降は即座に起動します。

## 使い方

起動するとトレイに常駐し、既定では**バッファリングが自動で始まります**。

| 操作 | 既定キー | 内容 |
| --- | --- | --- |
| 直前を保存 | `Alt + F10` | 直近 N 秒（既定 60 秒）を MP4 で保存 |
| 録画 開始/停止 | `Alt + F9` | 通常の連続録画。停止時に保存 |
| バッファ 開始/停止 | `Alt + F8` | インスタントリプレイの ON/OFF |

> **キーが他のアプリに使われている場合は自動で切り替わります。**
> NVIDIA Share（GeForce オーバーレイ）は既定で `Alt+F8/F9/F10` を使うため、
> その場合は `Ctrl+Alt+F10` など空いているキーに自動で切り替え、画面に通知して設定に保存します。
> 実際に有効なキーは「今すぐ保存」ボタンと設定タブに表示されます。

- 保存先は**ホーム画面の下部に常に表示**されます。書き込めない場所が指定されている場合は自動的にフォールバックします。
- クリップを**ダブルクリック**すると関連付けられたプレーヤーで開きます。
- 「フォルダ」ボタンで開けない環境では、パスを自動でクリップボードにコピーして通知します。
- ウィンドウは固定サイズで、右上のボタンは **最小化 / 閉じる**（どちらもトレイに残り録画は継続）。終了はトレイメニューの「終了」から。
- **言語**: 起動時は英語。ヘッダー右上の `日本語` を押すと即座に日本語へ切り替わり、設定に保存されます。

### 画面の見かた

ホームは**上から「状態 → 保存できる長さ → 操作 → 数値 → クリップ」**の順に並べています。
操作ボタンは右上にまとまり、クリップ一覧が残りの高さをすべて使います。

- 右上: **今すぐ保存**（ホットキー表示付き）/ 録画 / バッファ

- **状態**: `待機中` / `録画中` / `保存中…`（色 + アイコン + 一言だけ）
- **`300 秒`**: 何秒さかのぼれるかを数字だけで表示
- **バー**: `103.1 / 300 秒`。溜まり具合が分かります
- その下に FPS・ドロップ・CPU・GPU・ビットレート・解像度を 1 行で
- 最下部の保存先パスはクリックでフォルダを開きます

### 設定項目（最小限）

| 項目 | 説明 |
| --- | --- |
| 画面 | キャプチャするモニター（**実際のサムネイル**付き）。最上部 |
| 何秒前まで保存しますか？ | 15–600 秒。使うメモリの目安と「ディスクに保存」の ON/OFF |
| クリップの保存先 | フォルダ指定（空欄なら「ビデオ」） |
| クリップの画質 | フレームレート / ビットレート / プリセット（小さめ・標準・高画質・最高） |
| 音声 | ゲーム音声の ON/OFF・デバイス、**マイクの ON/OFF・デバイス・音量（0–200%）・入力レベル・遅れ補正** |
| ホットキー | **ボタンを押してキーを押すだけ**（修飾キー＋キー対応、Esc で取消） |
| 起動と動作 | 起動と同時にバッファ開始 / Windows 起動時に開始 / 最小化で起動 / 保存後にフォルダを開く |
| 詳細設定（折りたたみ） | コーデック / レート制御 / 音声のずれ補正（初期値のままで通常は不要） |

**設定は自動保存されます**（「適用」ボタンはありません）。キャプチャに関わる変更は
自動でパイプラインを再起動して反映します。

> 保存先が環境によって変わる場合（権限の違いなど）でも設定を失わないよう、
> 起動時に他の候補フォルダの `settings.json` を引き継ぐ処理を入れています。

## 仕組み（実装の詳細）

### フラグメント = 「切り取り可能な最小単位」

ffmpeg には次のように出力させています。

```
-f mp4 -movflags +frag_keyframe+empty_moov+default_base_moof pipe:1
```

`+frag_keyframe` により、**キーフレームごとに `moof`（フラグメント）が作られます**。
`-g <fps>` でキーフレーム間隔を 1 秒にしているので、フラグメントは 1 秒単位。

Clyppey はこのバイト列を stdout から読み取り、MP4 のボックス構造を自前で解析して

```
初期化セグメント (ftyp + moov)   … 1 回だけ保持
フラグメント (moof + mdat) × N    … リングバッファに保持（古いものから破棄）
```

に分解します。保存時は「初期化セグメント + 選んだフラグメント」をそのまま
ffmpeg の標準入力に流し、`-c:v copy` で MP4 に詰め替えます。

### 音声（ゲーム音 + マイク）

WASAPI ループバック（ゲーム音）と WASAPI キャプチャ（マイク）を**別々のリングバッファ**に保持し、
保存時にだけ WAV に切り出して 1 本のトラックにミックスします。

```
[ゲーム音] → aresample → aformat(stereo) → volume=1.0 ┐
                                                     ├→ amix → alimiter → AAC
[マイク]   → aresample → aformat(stereo) → volume=0–2 ┘
```

クリップ長は**映像側**が基準です（`-shortest` は ffmpeg 7.x で無限音声フィルタと組み合わせると
終了しなくなるため、`-t` で明示しています）。

### FFmpeg コマンド（実際に生成されるもの）

```
ffmpeg -hide_banner -nostdin -loglevel warning -nostats -progress pipe:2
  -f lavfi -i ddagrab=output_idx=0:framerate=60:draw_mouse=1
  -c:v h264_nvenc -preset p4 -tune ull -g 60 -bf 0 -rc-lookahead 0 -delay 0 -surfaces 4
  -profile:v high -rc cbr -b:v 35000k -maxrate 35000k -bufsize 70000k
  -f mp4 -movflags +frag_keyframe+empty_moov+default_base_moof pipe:1
```

`-progress pipe:2` により、ffmpeg 自身が報告する実測 fps・ドロップ数・ビットレートを
UI にそのまま表示しています（推測値ではありません）。

## 検証（CLI）

UI を介さず、エンジンだけを検証できます。

```powershell
$cli = "src\Clyppey.Cli\bin\Debug\net8.0-windows\clyppey.exe"

& $cli probe                        # 環境・エンコーダ・モニターの一覧
& $cli selftest --seconds 18        # エンドツーエンド自動検証（17 項目）
& $cli bench --seconds 30           # 負荷計測（CPU / GPU / fps / ドロップ）
& $cli save --seconds 30            # 直近 30 秒を保存
& $cli record --seconds 15          # 15 秒の通常録画
& $cli record --seconds 5 --no-audio   # マイクだけを録る（マイク検証用）
& $cli monitors --out .\shots       # 各モニターのプレビュー画像
```

UI の見た目は実際に描画して確認できます（開発用）。

```powershell
src\Clyppey.App\bin\Debug\net8.0-windows\Clyppey.exe --screenshot out.png --tab 0 --lang ja
```

## トラブルシューティング

| 症状 | 対処 |
| --- | --- |
| エンコーダが「利用不可」と出る | 診断タブで理由を確認。NVIDIA ならドライバ更新、または AMD/Intel のエンコーダが選ばれるか確認 |
| NVENC が使えない（古いドライバ） | 同梱 ffmpeg は API 12.2 対応です。それより古い場合はドライバ更新が必要です。自動で AMF/QSV/x264 にフォールバックします |
| **ホットキーが効かない / 「他のアプリが使用中」と出る** | **NVIDIA Share（GeForce オーバーレイ／ShadowPlay）は既定で Alt+F8・F9・F10 を使用します。** Clyppey は空いているキーへ**自動で切り替えて**通知・保存します。それでも解決しない場合は、NVIDIA 側のインスタントリプレイを無効にするか、設定で別のキーに変更してください |
| マイクが入らない | 設定の「マイクの音も録音する」が ON か、入力レベルが動いているかを確認。Windows のマイク許可も確認してください |
| 音声がずれる | 詳細設定の「音声のずれ補正」で調整 |
| バッファが溜まらない / エラーになる | 排他的フルスクリーンでは Desktop Duplication が失敗することがあります。ボーダーレス／ウィンドウモードにしてください |
| 画面が真っ黒で録れる | モニター選択がずれている可能性。設定のサムネイルで確認してください（DRM 保護された映像は原理的に録画できません） |
| 設定が保存されない | 自動保存です。保存先フォルダが書き込み可能か診断タブで確認してください |

ログは設定フォルダ内の `clyppey.log`、診断タブからも確認できます。

## 音声の同期について

録画経路の音声オフセットは実測して補正しています（白色フラッシュとビープを同時に出して測る方式。
詳細は [AGENTS.md](AGENTS.md) §12）。環境によって数十 ms 残る場合は、
設定 → 詳細設定 → 「音声のずれ補正」で ±500 ms 調整できます。

## 既知の制限

- **HDR は SDR に変換**して録画します（10bit 出力は未使用）。
- **排他的フルスクリーン**のゲームでは Desktop Duplication が使えない場合があります（ボーダーレス推奨）。
- 録画範囲はモニター全体で、特定ウィンドウだけを切り出す機能はありません。
- 既定ではバッファをディスクに置くため、**バッファ長 × ビットレート分の空き容量**が必要です（例: 300 秒 / 40 Mbps で約 1.5 GB）。異常終了時の残骸は次回起動時に自動削除します。
